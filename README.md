# Motorcycle System

Track your motorcycle maintenance (engine oil, coolant, tyres, chain, brakes and more) and find motorcycle workshops near you on a map.

- 🔧 Maintenance logs and reminders by distance or time
- 🗺️ Nearby workshops with Google Maps (asks for location permission first)
- 🌐 Web app deployed on Vercel
- 🤖 Android app built from the same code with Capacitor (`com.fadzyll.motorcycle`)

See the full [Technical Plan](docs/TECHNICAL_PLAN.md).

## Features so far

- **Accounts:** register with name, email and password → activate with a code sent by email → sign in with email + password (forgot-password reset by code)
- **Motorcycles:** add, edit and delete bikes (scooters automatically track the CVT belt instead of the chain)
- **Maintenance schedule:** 16 common items with default intervals, editable per bike (every X km or Y days, whichever comes first), plus your own custom items
- **Log a service:** several items in one visit, with cost per item, workshop and notes
- **Odometer updates**, used to predict when items will be due from how much you ride
- **Dashboard:** what's overdue or due soon across all bikes
- **Service life bars:** each item shows how much of its interval is used since the last service (fills as you ride and as time passes)
- **GPS ride tracking:** measure a ride with the phone's location and add the km to the odometer — also works for bikes with a broken meter. Only distance and time are saved, never the route.
- **Light / dark mode** and a **desktop layout** for laptops
- **Service history** per bike with the total spent

## Tech stack

Vite + React + TypeScript · Tailwind CSS · React Router · TanStack Query · Supabase (Postgres, Auth, Storage) · Vercel Functions (`/api`) · Capacitor (Android) · Vitest · oxlint

## Getting started

### 1. Install

Requires Node.js 22+.

```bash
npm install
```

### 2. Create the Supabase project

1. Create a project at [supabase.com](https://supabase.com).
2. **SQL Editor** → paste `supabase/migrations/20261104000000_init.sql` → **Run**.
3. **Authentication → Email templates → Magic Link**: make sure the email contains `{{ .Token }}` so users get a **6-digit code**, e.g.
   ```html
   <h2>Your sign-in code</h2>
   <p>{{ .Token }}</p>
   ```
4. **Project Settings → API**: copy the Project URL and the `anon` public key.

### 3. Environment variables

```bash
cp .env.example .env.local
```

Fill in `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`. Everything starting with `VITE_` is bundled into the app (including the Android APK), so **never put secrets in `VITE_` variables**.

### 4. Run

```bash
npm run dev
```

Open http://localhost:5173.

## Deploy to Vercel

1. Vercel → **Add New Project** → import this repo. The framework is detected as **Vite** (`vercel.json` sets the build and SPA rewrites).
2. Add environment variables: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (Production and Preview).
3. Deploy. Check `https://<your-app>.vercel.app/api/health` returns `{"ok":true,...}`.
4. Set **Settings → Git → Production Branch** to `main`. Pushes to `develop` and feature branches get Preview deployments.

## Android app

Requires [Android Studio](https://developer.android.com/studio) (includes the JDK and Android SDK).

1. In `.env.local` set `VITE_API_BASE_URL` to your Vercel URL (inside the app the page runs on `https://localhost`, so the API needs a full URL).
2. Connect a phone with USB debugging on (or start an emulator), then:
   ```bash
   npm run android:run
   ```
   Or `npm run cap:sync` and `npm run android:open` to build from Android Studio.
3. Run `npm run cap:sync` after every web change you want in the app.

CI also builds a debug APK on every push/PR — download it from the workflow run's **Artifacts**.

## Branching workflow

| Branch | Purpose | Deploys to |
| --- | --- | --- |
| `main` | Stable, released code only | Vercel Production |
| `develop` | Integration branch — next release | Vercel Preview |
| `feature/<name>` | One feature or fix, branched from `develop` | Vercel Preview (per PR) |
| `hotfix/<name>` | Urgent fix, branched from `main`, merged into `main` **and** `develop` | — |

1. `git checkout develop && git pull` → `git checkout -b feature/add-bike-form`
2. Commit, push, open a Pull Request into **`develop`**. CI must pass.
3. To release: open a PR **`develop` → `main`**, merge, and tag it (`v0.1.0`). Build the Android release from that tag.

Recommended GitHub settings: default branch `develop`; branch protection on `main` and `develop` (require a PR and passing CI, no force pushes).
